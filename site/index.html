Bring your own FSX installation

openFSX includes no original game resources. The content tools read your local installation without launching or modifying FSX. Aircraft, textures, scenery and SDK binaries stay out of the repository.

What is openFSX?

A project to explore a modern engine for the world of Microsoft Flight Simulator X, inspired by openOMSI. The target is FSX 1:1 across interface, behavior, content and APIs, using an independently written runtime. Compatibility must be verified one subsystem at a time; parity has not been established.

Today, that means inspecting content, viewing textured models and testing keyboard-controlled C172 flight, including fixed-wheel ground roll and departure. Scenery, broader landing behavior and add-on APIs remain ahead.

openFSX / Get started

Get started

Build the research tools from source.

i

No packaged simulator release yet

Build the content tools, textured viewer and initial airborne flight mode from source with stable Rust and the Windows MSVC C++ build tools. Flight behavior is not validated against recorded FSX trajectories.

1. Get the source

git clone https://github.com/openFSX-project/openFSX.git
cd openFSX

2. Inspect your installation

Replace the path with your own FSX folder. Use Windows-1252 only for files in that code page; omit the flag for ASCII/UTF-8.

cargo run -- inspect "D:/Games/FSX" --windows-1252

3. Open a model

The native viewer requires current Vulkan or DirectX 12 drivers. This example selects the Blue/Gold C172 livery from your own installation.

cargo run -p fsx-app --features viewer --bin openfsx-viewer -- "D:/Games/FSX/SimObjects/Airplanes/C172/model/cessna172sp.mdl" --lod 150 --texture-dir "D:/Games/FSX/SimObjects/Airplanes/C172/texture.1"

Drag to orbit, scroll to zoom, use arrow keys to rotate, press R to reset and Esc to close.

Viewer controls and limitations →

4. Try the airborne prototype

This mode takes an aircraft folder and resolves its model, livery and legacy AIR data. It starts at 90 kt and 300 m above a flat test surface.

cargo run -p fsx-app --features viewer --bin openfsx-viewer -- "D:/Games/FSX/SimObjects/Airplanes/C172" --fly --variant 0 --windows-1252 --lod 150

Down/Up: pull/push · Left/Right: bank · Q/E: rudder · Page Up/Down: throttle · P: pause · R: reset. See the flight guide for trim controls, tests and limitations.

5. Start on the test runway

Add --ground to begin with fixed-wheel suspension settled and the parking brake applied.

cargo run -p fsx-app --features viewer --bin openfsx-viewer -- "D:/Games/FSX/SimObjects/Airplanes/C172" --fly --ground --windows-1252 --lod 150

B: toggle parking brake · F4/F1: full/idle power · Space: hold wheel brakes · Q/E: rudder and nosewheel steering. R restores the selected start. Departure is experimental; sustained control and landing performance are not validated. Read the ground subset and observed results.

6. Open the FSX-style menu

Windows requires WebView2. The prototype reads your installed UI skin and aircraft resources. Its live 3D preview uses the shared renderer; drag to orbit and use the wheel to zoom. Select an aircraft and use FLY NOW! to start the experimental runway mode; Esc returns to the menu. Other sections remain unimplemented. Add --debug-hud to a direct flight command for experimental telemetry.

cargo run -p fsx-app --features viewer --bin openfsx-viewer -- "D:/Games/FSX" --menu

Verify a change

cargo test --workspace --locked
cargo fmt --all --check
cargo build --locked -p fsx-app --features viewer --bin openfsx-viewer
node scripts/build-site.mjs --check

Tests use original synthetic data. Your FSX files remain local and must not be committed.
